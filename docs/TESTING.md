## 验收映射与缺口

A01–A19、A21–A23、A27–A28、A32–A34 有策略/注入测试的部分覆盖，不等同全部硬件通过。A20 单实例/UI、A24 关于、A25 登录启动必须单独检查；A26 可通过代码审计与运行核验；A29–A31 除 C 摘要单测外，还缺系统音频权限允许/拒绝、Tap 生命周期及真实静音流实测。真实写后回读、外部多声道、睡眠唤醒、音频服务重启仍需实机测试。

测试不自动升高系统音量。初始系统音量为 0，随后外部操作变为约 8.8%；首个 GUI 观察窗口超过 5 分钟未见归零，未据此记为通过。随后停止旧测试实例，用显式 `--verify-auto-zero --confirm-zero` 在独立实例设 1 分钟临时等待（不保存设置），观察 waiting → playing → waiting → zero，最终 AUTO_ZERO_HARDWARE=PASS，音量回读为 0，播放监听由 97 降为 0，基础监听 11。验证没有恢复非零音量；GUI 的默认设置仍为 5 分钟。

后续启动版本的 `--status` 实测 state=zero、volume=0、monitorActive=false、playbackListeners=0、signalActive=false、listeners=11、enabled=true、minutes=5。状态只在请求时导出，不后台写日志。

原生设置/关于视图已生成本地缓存图并检查可读布局；真实设备名称未提交仓库。CUA 的窗口截图接口超时，因此没有将其视为完整外部 UI 自动化通过。窗口构造与关闭释放使用 release 也生效的 precondition 验证。

长期性能与全部设备矩阵未通过前仅发行开发预览。首个 GUI 未归零观察的原因未独立定位，不应将后续短时通过解读为所有 GUI 长时场景均通过。
