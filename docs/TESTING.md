## 验收映射与缺口

A01–A19、A21–A23、A27–A28、A32–A34 有策略/注入测试的部分覆盖，不等同全部硬件通过。A20 单实例/UI、A24 关于、A25 登录启动必须单独检查；A26 可通过代码审计与运行核验；A29–A31 除 C 摘要单测外，还缺系统音频权限允许/拒绝、Tap 生命周期及真实静音流实测。真实写后回读、外部多声道、睡眠唤醒、音频服务重启仍需实机测试。

自动化测试不会提高真实系统音量。历史显式 `--verify-auto-zero --confirm-zero` 测试只验证归零，不测试 v0.3.0 的确认恢复。恢复路径目前仅通过注入服务验证，不宣称真实 HAL 多通道恢复、辅助功能允许/拒绝、浏览器辅助进程映射或多显示器定位已实机通过。

`--status` 使用 `recoveryMonitoringActive` 区分自动保护监听和归零后的恢复事件监听，并新增 `recoveryConfirmationActive` 区分等待播放与正在确认持续播放。状态只在请求时导出，不后台写日志。

原生设置/关于视图已生成本地缓存图并检查可读布局；真实设备名称未提交仓库。CUA 的窗口截图接口超时，因此没有将其视为完整外部 UI 自动化通过。窗口构造与关闭释放使用 release 也生效的 precondition 验证。

长期性能与全部设备矩阵未通过前仅发行开发预览。首个 GUI 未归零观察的原因未独立定位，不应将后续短时通过解读为所有 GUI 长时场景均通过。

## v0.3.1 静音流误报修正

新增四个控制器回归：严格模式自动归零后，即使原播放器进程仍报告输出，只要 Signal Tap 仍判定为数字静音就不提示；随后出现非零信号才提示一次，连续有声不重复，重新静音后再次有声可再提示。另验证恢复阶段的信号读取失败，以及切换检测模式或从保护名单排除当前设备时，都会撤销恢复凭据、释放监听并保持安全状态。信号层单测锁定 600 ms 防抖边界：不足 600 ms 的无声间隔仍视为同一段播放，达到边界才形成下一次可提示的空闲沿。

该修正复用归零前已经运行的 Signal Tap，不重新申请权限、不新建第二个 Tap。真实系统音频的“持续静音后恢复有声”端到端测试仍会涉及系统音频权限和真实播放器，当前以注入回归覆盖，不冒充实机通过。

## v0.3.2 品牌与恢复浮层

所有 App 自建 `NSAlert` 通过同一工厂显式设置声音守卫彩色 App 图标，覆盖静音流确认、恢复功能确认、错误和许可证；不依赖系统默认或图标缓存。恢复面板检查固定 420×264pt、品牌/问题/播放来源文字、归零前音量卡片、倒计时，以及两个 185×34pt 对齐矩形；右侧恢复按钮使用品牌青绿色填充。明暗图为原生离屏合成，不等同外部真实窗口截图；VoiceOver、缩放显示和真实多屏位置仍需人工验收。

## v0.3.3 恢复选择语义

控制器回归验证：错误提示 ID 不改变恢复上下文；点击“保持静音，不再提醒”后清除凭据、释放监听、不写入非零音量，并且即使随后停止再播放也不再提示。UI 检查分别触发恢复、保持静音、倒计时和左上角关闭，确认只有两个底部按钮调用选择回调；同时继续验证两个不同长度文案的按钮对齐矩形均为 185×34pt、没有默认回车键。真实播放器和系统音量恢复仍未在本轮自动执行，避免未经用户单独确认提高真实系统音量。

## v0.3.4 有声确认时长

偏好测试覆盖默认 2 秒、500 毫秒和 30 秒边界、越界回退、JSON 往返及旧偏好迁移。控制器测试验证播放开始后不足时长不提示、截止时提示、播放停止后重新计时、确认时长修改后重新计时、取消任务的旧回调不能提示，以及默认和严格两种检测路径仍保持单段去重。UI 检查覆盖默认“2 秒”、`0.5 秒`与 `750 毫秒`输入。测试使用可控单调时钟，不真实等待、不提高系统音量。

## v0.3.5 重新核对生命周期

注入控制器测试复现故障后的手动重试，验证 3 秒冷却前不调用 `audio.start()`，设备回调、配置刷新和重复重试不能提前或重复重建；截止时只启动一次并重新建立完整空闲周期。另验证退出及睡眠使旧回调失效、睡眠状态正确显示、唤醒立即重新初始化。UI 检查验证“正在重新核对”期间菜单命令禁用。自动化不等同真实 Core Audio Tap 回收实测，安装后的只读状态另行记录。
