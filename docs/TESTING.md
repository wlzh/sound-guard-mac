## 验收映射与缺口

A01–A19、A21–A23、A27–A28、A32–A34 有策略/注入测试的部分覆盖，不等同全部硬件通过。A20 单实例/UI、A24 关于、A25 登录启动必须单独检查；A26 可通过代码审计与运行核验；A29–A31 除 C 摘要单测外，还缺系统音频权限允许/拒绝、Tap 生命周期及真实静音流实测。真实写后回读、外部多声道、睡眠唤醒、音频服务重启仍需实机测试。

自动化测试不会提高真实系统音量。历史显式 `--verify-auto-zero --confirm-zero` 测试只验证归零，不测试 v0.3.0 的确认恢复。恢复路径目前仅通过注入服务验证，不宣称真实 HAL 多通道恢复、辅助功能允许/拒绝、浏览器辅助进程映射或多显示器定位已实机通过。

`--status` 新增 `recoveryMonitoringActive`，区分自动保护监听和归零后的恢复事件监听。状态只在请求时导出，不后台写日志。

原生设置/关于视图已生成本地缓存图并检查可读布局；真实设备名称未提交仓库。CUA 的窗口截图接口超时，因此没有将其视为完整外部 UI 自动化通过。窗口构造与关闭释放使用 release 也生效的 precondition 验证。

长期性能与全部设备矩阵未通过前仅发行开发预览。首个 GUI 未归零观察的原因未独立定位，不应将后续短时通过解读为所有 GUI 长时场景均通过。

## v0.3.0 恢复提醒验证

纯逻辑覆盖默认关闭、旧偏好迁移、5–600 秒边界、各通道音量快照、自动归零建立凭据、手动归零不建立、播放开始沿、连续播放不重复、停止后再次提示、设备变化失效、关闭功能释放监听、辅助监听失败不破坏已完成归零，以及明确确认后的恢复。UI 覆盖开关、权限按钮关闭态、恢复面板品牌/样式、无默认回车键、保持静音、恢复、超时和旧请求关闭。

仍缺真实自动归零后启动 Safari/Chrome/音乐 App 的端到端测试、允许与拒绝辅助功能、多窗口/多显示器/多 Space、蓝牙/USB/HDMI、进程 PID 缺失、系统睡眠和 Core Audio 重启。实际点击恢复会提高真实音量，未经用户单独同意不自动执行这类硬件测试。

只读 release 恢复监听探针运行 60.010 秒，平均 CPU 0.00180%、峰值 RSS 8.078 MiB、总监听 98、播放监听 95、Signal Tap=false。该过程未改音量；监听数量取决于当时进程，只证明短时事件监听开销，不证明完整 UI 或长期稳定性。
