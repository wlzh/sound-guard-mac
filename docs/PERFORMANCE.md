# 性能机制与测量

## 机制

默认模式无音频采样、无常驻周期扫描、只有事件监听；空闲时至多一个单次截止定时器。菜单和设置不进行后台动画。恢复提醒关闭时，音量 0、静音、暂停、未勾选设备停止播放检测，只保留基础设备事件。

恢复提醒开启且由本 App 自动归零后，默认检测模式额外保留 Core Audio 进程输出事件监听，不启动 Signal Tap、不分析音频样本、不周期轮询。弹窗显示期间只有一个 1 秒 UI 倒计时 Timer，关闭、取消、超时、恢复或请求失效后释放。定位窗口仅在触发时查询辅助功能树。

v0.3.4 的“有声确认”不新增监听。默认模式收到播放开始事件后只建立一个可取消的单次截止定时任务；停止播放、设置或设备变化时释放。严格模式复用已有 0.5 秒摘要/健康检查，不提高频率。确认状态只增加时间戳和布尔状态，设置 500 毫秒或 30 秒不会改变常驻轮询频率；实际提示精度受现有 0.5 秒严格模式检查周期和 100 毫秒定时器容差影响。

v0.3.5 的手动“重新核对”先停止监听并使用一个 3 秒单次定时任务等待 Core Audio 回收，再建立一次检测。冷却期没有音频采样、轮询或动画；重复点击和设备回调不会增加任务，退出或睡眠会取消任务。该修复只影响显式重试路径，不改变正常检测频率。

v0.3.1 例外：用户已经主动开启“静音流也计时”时，自动归零后的恢复等待会继续复用同一个 Signal Tap，以区分持续数字静音和真正恢复有声；不会再同时建立进程事件监听。默认检测模式及恢复提醒关闭时的资源行为不变。

严格模式启用且设备可保护时，增加硬件音频回调与 0.5 秒摘要/健康检查。实时侧只扫描 Float32 到第一个非零样本并写原子时间戳，没有音频文件、队列堆积或逐帧 UI。严格模式不承诺与默认模式同等开销。

## 可重现测量

v0.3.6 将严格检测聚合设备配置为不等待播放源，避免无播放时无回调。仍只有原有一个 Tap 和 0.5 秒健康检查，没有增加周期任务；严格空闲现在会实际接收静音样本，其性能不能沿用此前故障停机时的低占用。默认模式不变。`signalHasFreshSamples` 仅在请求诊断时读取原子摘要，不保存音频。新增 `--probe-signal-retry` 为手动、三轮、零音量、无写入探针，不属于常驻后台任务。

release App 可执行 `--probe-zero 60`（最长 3600 秒）：只在当前输出音量为 0 且状态正确时运行。它使用进程 rusage 统计 CPU 增量及峰值 RSS，并输出监听数量；不修改音量。此探针为无 AppKit 窗口的核心驻留测量，不能冒充完整菜单栏 App 的内存。

完整 App 应以活动监视器或 Instruments 分别测量零音量、默认播放、空闲等待、严格模式各至少 10 分钟；再做 8 小时长期运行。报告必须包含系统、硬件、版本、构建模式、时间、样本和工具，测试时不得自动调高扬声器音量。

目标：默认模式零音量平均 CPU ≤0.1%、峰值/驻留 RSS 预算 30 MiB；默认播放/计时 CPU ≤0.5%；8 小时无持续增长。目标不是当前结论；GUI 与核心分开报告，未测场景标 NOT RUN。结果见 [测试报告](TESTING.md)。

## 2026-09-10 短时结果

macOS 15.6 / Apple Silicon，v0.1.0 build 1，release：核心零音量探针运行 60.187 秒，CPU 增量平均 0.04013%，rusage 峰值 RSS 8.406 MiB；11 个基础监听，0 播放监听，0 Signal Tap。

新启动完整 App 的 ps 快照：29 秒时 RSS 25,232 KiB，121 秒时 26,944 KiB（26.31 MiB），两次瞬时 CPU 均 0.0%。这不是完整窗口生命周期峰值，也不是 10 分钟平均。早期打开窗口后的测试实例曾达到约 78.6 MiB；后来增加窗口关闭释放，但 AppKit/系统缓存仍可能保留，不能承诺使用过程中始终低于 30 MiB。

10 分钟各运行状态、严格模式消耗、8 小时驻留均 NOT RUN。原始截图含本机设备名称，仅保存在被忽略的 local-results，不纳入发行包。

## v0.2.1 展示更新

菜单顶部布局改变，不增加定时器、音频采样、后台日志或设置迁移。仍在菜单打开时构造、关闭时释放头部；旧版本的测量不能作为本版本新增实测数据。

## v0.3.0 恢复提醒

新增模式的理论开销与默认零音量休眠不同，因此旧版 0 播放监听和 CPU 数据不能套用。2026-09-14 使用 release `--probe-recovery-monitor 60` 在零音量下只读测量 60.010 秒：平均 CPU 0.00180%，峰值 RSS 8.078 MiB，98 个总监听、95 个播放监听，Signal Tap=false。监听数量随当时系统音频进程数变化；这是无 AppKit 窗口的短时核心探针，不代表完整 App 或长期结果。

完整 App 的 10 分钟、8 小时、弹窗持续显示及多播放进程性能仍需实测，未完成前只标开发预览。
