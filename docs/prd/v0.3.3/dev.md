# v0.3.3 技术设计

## 上游

上游仍是 `GuardController` 在本 App 自动归零后保存的内存 `RecoveryContext`，以及默认模式的播放进程沿或严格模式的非零信号沿。`RecoveryPrompt` 的 ID、设备、原音量、进程和超时时长结构不变；偏好格式和辅助功能申请时机不变。

## 状态与回调

`RecoveryPromptPresenter` 将两个底部按钮分别发送 `onKeepSilent` 和 `onRestore`。`GuardController.keepSilent(for:)` 只接受当前匹配 ID，清除上下文、关闭恢复监听、记录显式动作并刷新状态；它不写音量。错误或过期 ID 是无副作用操作。

标题栏关闭和倒计时只销毁面板、Timer 与面板内请求引用，不回调控制器，因此控制器保留恢复上下文和当前播放沿状态。连续播放不会立刻重弹；播放先变为停止、随后再次开始时才产生新提示。右侧恢复仍调用既有 `restoreVolume(for:)`，复核后才写入原音量。

## 下游与资源

显式保持静音的下游结果是系统音量继续为 0、恢复凭据清除、Core Audio 恢复监听释放，后续不会再为这次自动归零提示。临时关闭的下游结果仅是 UI 和单个 1 秒倒计时 Timer 释放；既有低开销播放事件监听或严格 Signal Tap 按设置继续等待新的播放沿。

没有新增权限、持久化字段、后台刷新、辅助进程或网络访问。测试注入假音频服务验证凭据和监听生命周期，UI precondition 独立验证回调分流、按钮尺寸、关闭和超时。
