# v0.4.7 产品需求文档

2026-11-07，build 23，开发预览。本轮由用户实机截图反馈驱动：恢复提示弹窗仍显示“某个 App 已开始播放”，v0.4.6 新增的“不再提醒”链接未出现——触发来源是无 bundle 的进程，LaunchServices 解析不到身份。本轮补齐裸进程的名称与身份解析，使来源显示与一键例外对全部来源生效。不改变保护行为或偏好格式。

## 背景证据

用户截图（v0.4.6 运行中）：提示显示“某个 App 已开始播放”且无“不再提醒”链接。代码证据：`SystemAudio.playbackProcess(pid:)` 仅经 NSRunningApplication 解析 bundle 身份，失败时返回裸 PID，提示端 `appDescriptor` 因无 bundleId/路径返回 nil，链接按设计隐藏。用户偏好例外名单已有 MuMu、WeChat、Arc 等 bundle App，说明剩余触发源是 bundle 外进程。

## 目标

无 bundle 的播放进程在提示中显示真实进程名，并可一键按可执行路径加入例外；路径身份与 PID 无关，重启后同一可执行文件仍匹配。bundle App 行为完全不变；读不到路径（进程已退出等）时维持既有回退。
