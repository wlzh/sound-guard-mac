# v0.4.3 产品需求文档

2026-11-05，build 19，开发预览。本轮针对两次实机诊断证实的检测故障停机（OSStatus 2003332927，设备切换竞态读取已消失对象），消除"必须人工点重新核对才恢复保护"的路径，不改变权限、默认功能或音量安全边界。

## 背景证据

诊断日志显示 2026-10-30、10-31、11-04 三次同一模式：恢复记录失效（设备变化）后约 40 秒内读取设备标识失败（'who?'），该错误不在临时白名单，控制器立即进入永久故障态；10-31 与 11-04 分别停机 7 与 13 小时，均由用户手工"重新核对"恢复并随即成功归零。

## 目标

设备切换竞态优先就地恢复：默认设备读取失败先重读一次，多数情况无感继续。仍失败的检测故障由心跳看门狗自动重建，不再依赖人工；写入故障锁、暂停、睡眠、冷却期间不自动动作。系统通知静默丢失时由周期复核兜底。诊断与状态导出可观测自动恢复过程。

## 验收

- [x] A01 'who?'（2003332927）归类为临时检测错误，允许既有 3/10/30 秒快速重建。
- [x] A02 默认设备读取临时失败时重读一次默认设备并检查新设备，路由切换竞态不进入故障态。
- [x] A03 重读仍失败时沿用既有快速重建与安全复核，不新增写入路径。
- [x] A04 快速重建耗尽后不再永久停机，心跳看门狗自动执行相当于"重新核对"的重建。
