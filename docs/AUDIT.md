# 全链路审计记录

v0.4.6 / build 22，2026-11-07。工作区起点为干净 main（v0.4.5 / build 21 已发），原基线 129 项测试 / 670 次断言通过。本轮由用户需求驱动：恢复弹窗内显示触发来源并提供一键“不再提醒”，把该 App 加入恢复提示例外；要求界面不变大。

## 实机证据与根因

弹窗副标题已显示来源 App 名，但加入例外需打开设置 → 恢复提示应用 → 从当前播放进程添加，路径长；用户希望弹窗内一键完成。例外机制（ignoredRecoveryApps、身份匹配、playbackWasIgnoredOnly 不弹窗路径）自 v0.4.0 起已存在并有注入回归覆盖，本轮仅前移入口，不改名单语义。

## 范围与结果

| 链路 | 审查与处理 |
| --- | --- |
| 来源识别 | appDescriptor 按顺序解析弹窗进程列表第一个可识别身份；名称与链接操作绑定同一身份 |
| 弹窗 UI | 来源行右端 12pt 链接“不再提醒”，同行右对齐、行宽上限 326pt，面板保持 420×350；无来源时不显示 |
| 点击语义 | 先关面板再回调；只写偏好、不写音量、不触发恢复或保持静音 |
| 偏好写入 | AppDelegate.ignoreRecoveryApp 按身份去重追加既有 ignoredRecoveryApps 字段，格式不变 |
| 后续行为 | configure 走既有 ignoredAppsChanged 分支作废当前提示资格；该 App 再播放命中“全部被忽略”路径不弹窗 |
| 文案与说明 | 链接工具提示说明效果与移除路径；设置页例外说明提及弹窗入口 |
| 文档 → 版本 | 同步 0.4.6 / build 22 全套入口；构建与安装分离 |

## 自动化证据

核心回归维持 129 项 / 670 次断言通过（控制器零改动，不新增注入回归）；原生 UI 自检新增例外链接断言（存在性、回调身份、面板尺寸、去重写入、无来源不显示）并通过，另有渲染预览像素级比对确认差异仅限来源行、底部按钮区逐字节一致。最终完整门禁和发行验证结果记录在[测试报告](TESTING.md)。

## 保留边界

- 来源识别依赖 bundleId/路径或 PID 反查；无法识别时不显示链接，仍可走设置入口。
- “不再提醒”一键生效并立即关窗，误点可在设置 → 恢复提示应用中移除（移除后恢复弹窗）。
- 与“保持静音，不再提醒”并存：前者跨设备跨会话针对该 App，后者针对本设备本次守望。
- 真实 App 触发弹窗并点击链接的实机验收（A30）未自动执行，不因 UI 自检通过宣称实机通过。
- 本地构建、安装、Git 提交、远端 CI 和公开 Release 是独立交付门禁，不相互推导；无 Developer ID/公证。
