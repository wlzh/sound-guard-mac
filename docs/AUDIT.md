# 全链路审计记录

v0.4.3 / build 19，2026-11-05。工作区起点为干净 main，原基线 118 项测试 / 567 次断言通过。本轮由两次实机诊断证据驱动（2026-10-31、11-04 检测故障停机 7 与 13 小时，均需人工"重新核对"恢复）。

## 实机证据与根因

诊断日志三次相同模式（10-30、10-31、11-04）：恢复记录因设备变化失效后约 40 秒内，读取设备标识失败（OSStatus 2003332927，'who?'）。该错误为 HAL 对已消失对象的应答——设备切换瞬间默认设备 ID 过期；不在临时错误白名单，控制器立即永久锁定检测故障。人工"重新核对"后一次重建即成功并完成自动归零，证明系统音频并无持续异常，属于可自愈竞态被误判为永久故障。

## 范围与结果

| 链路 | 审查与处理 |
| --- | --- |
| 故障分类 → 快速重建 | 'who?' 归入临时错误；默认设备读取竞态重读一次，多数无感恢复 |
| 故障锁 → 看门狗 | 检测故障锁定后每 30 秒自动重建，等效自动"重新核对"；不再永久停机 |
| 通知 → 周期复核 | 30 秒心跳复核设备/音量/播放，兜底监听静默失效；空闲截止保持绝对时间 |
| 写入安全锁 | 写后错误与恢复写入错误仍仅人工核对，看门狗与心跳不触碰 |
| 恢复确认 | 心跳保留候选与截止时间，不重复弹窗；既有失效复核全部保持 |
| 状态 → 诊断 | 持续故障节流（首次与每 20 次留痕），lastFault 静默刷新；64 条历史不被冲刷 |
| 状态导出 | 新增 sustainedFault、automaticRecoveryArmed；既有字段不变 |
| UI → 控制器 | 故障详情提示"将自动重试"；重试计数去掉"/3"上限；禁用规则不变 |
| 生命周期 | start/stop 启停心跳，deinit 兜底；暂停/睡眠/冷却期间心跳无操作 |
| 文档 → 版本 → 安装 | 同步 0.4.3 / build 19 全套入口；安装与构建明确分离 |

## 自动化证据

当前核心回归 123 项 / 610 次断言通过，新增 5 项控制器回归（看门狗重建、休眠复核、跳过矩阵、持续节流、恢复截止保持）；OSStatus 分类测试纳入 'who?'。最终完整门禁和发行验证结果记录在[测试报告](TESTING.md)。

注入服务可验证状态机与心跳行为，不等同真实 HAL 竞态注入。'who?' 重读路径与真实设备切换后的 60 秒自动恢复需实机验收（A32）。

## 保留边界

- Core Audio 同步 API 可能阻塞；退避与看门狗不是同步调用的硬超时，无法修复系统音频服务自身卡住。
- 心跳使默认模式不再是纯事件驱动：每 30 秒数十次属性读取的长期定量性能未测。
- 真实设备切换（拔插耳机/蓝牙/USB）触发 'who?' 后的自动恢复、MuMu、播放器、多通道、多屏、权限矩阵未完成。
- 写入故障锁保持人工处理是刻意保守；自动恢复从不调高音量、不恢复音量、不把故障期间算作空闲。
- 本地构建、安装、Git 提交、远端 CI 和公开 Release 是独立交付门禁，不相互推导。
